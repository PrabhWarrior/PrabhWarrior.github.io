How I build

Designing for the bad day, not the demo

I assume pods will crash, brokers will rebalance and networks will drop requests, and I design so none of that loses data or wakes anyone up.

  1. Fault tolerant by default

    Transactional outbox with a strict commit order, at-least-once delivery with deduplication, and every pipeline tested against pod crashes, OOM kills and rebalances.

  2. Scale by partitioning

    Partition-owned processing so work scales horizontally without shared locks, plus lag-based autoscaling with KEDA and stable group membership across restarts.

  3. Robust under pressure

    Backpressure through bounded queues, retries with exponential backoff, dead-letter routing and idempotent handlers, so a slow dependency can't take the system down.

  4. Measure honestly

    Benchmarks under production settings, not developer defaults. I once found our throughput numbers were inflated because fsync was being skipped, and fixed the test before trusting the result.
